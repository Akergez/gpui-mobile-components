Colour

The previews use the schemes that adaptive-colors actually produces from each application's fallback seed, with the TonalSpot variant. Use the switch at the top to change the scheme. On a device the seed comes from the system: the accent from the settings portal on Linux, the wallpaper palettes on Android 12+. Both skins read the same roles. Pointer reads them through the gpui-kit theme names, Touch through M3 role names.

/// The colours of the touch skin: the scheme's roles while the scheme is worn,
/// otherwise the nearest the active theme has. Never paint from cx.scheme() directly.
pub trait TouchColors { fn touch(&self) -> TouchPalette; }
impl TouchColors for App {
    fn touch(&self) -> TouchPalette {
        let theme = self.theme();
        match AdaptiveColors::global(self).worn(theme.mode) {
            None => TouchPalette::from_scheme(self.scheme()),
            Some(_) => TouchPalette::from_theme(theme),
        }
    }
}

The design system does not add a colour engine. It uses gpui_adaptive_colors::init, set_source, wear/wear_scheme, and on Android refresh(cx) on resume. Light or dark stays Theme::change through gpui_android_glue::appearance::change_to, which also sets the status bar's icons.
