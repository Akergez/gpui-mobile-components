How it fits together

There is one new crate, gpui-adaptive (in this repository), between the toolkit and the apps. It adds no new engine: colours stay gpui-adaptive-colors, Android stays gpui-android-glue, and widgets stay gpui-kit wherever gpui-kit already has the behaviour.

aiddiction · matterfast · money-manager          feature code: Screen, Collection, Form, Command … only
        │
gpui-adaptive  (this repo)                         intents; each module = pub API + private pointer.rs / touch.rs
  ├─ form.rs        InputMode, WidthClass, Form::of
  ├─ scale.rs       radii, type, motion, density per skin (own Global)
  ├─ colors.rs      TouchPalette: cx.scheme() while the scheme is worn, else from cx.theme()
  ├─ motion/        springs, ripple element, shared-axis transition
  ├─ navigator/ screen/ destinations/ sheet/ panel/ dock/
  ├─ command/ item_actions/ confirm/
  ├─ form/ choice/ lookup/ date_field/ amount/ composer/
  └─ collection/ records/ feed/ board/ notice/ banner/ empty/ identity/
        │                  │                         │
gpui-kit 0.7      gpui-adaptive-colors       gpui-android-glue 0.4 (+ gpui-mobile rev 9075e3a)

Initialisation, the same in all three apps

gpui_kit::init(cx);
gpui_adaptive_colors::init(Options::new(Color::from_u32(SEED)).remembered(remembered), cx);
gpui_android_glue::init(cx);                 // run() does it on Android
gpui_adaptive::init(input, cx);              // Touch from android_main's start, Pointer from main()
