Navigator: columns when there is room, a stack when not

The app gives routes. Each route may name a companion, the route shown beside it when there is room: a channel's companion is the channel list, a record's is the records. With room, the Navigator lays out the companion chain as columns. Without room, it shows the top of the stack with a push transition, predictive back and swipe back. matterfast's layout/split.rs ("on a phone the list is the main screen, as it is in Telegram") and aiddiction's shell.rs back handling become this one intent.

pub trait Route: Clone + PartialEq + 'static {
    /// What is shown beside this route when there is room for it.
    fn companion(&self) -> Option<Self>;
    /// A page that scrolls sideways gives up swipe-back (glue's rule).
    fn scrolls_sideways(&self) -> bool { false }
}
pub struct NavigatorState<R: Route> { stack: Vec<R>, back: Option<back::Guard> }
impl<R: Route> NavigatorState<R> {
    pub fn push(&mut self, route: R, cx: &mut Context<Self>);
    pub fn replace_root(&mut self, route: R, cx: &mut Context<Self>);   // Destinations
    pub fn back(&mut self, cx: &mut Context<Self>) -> bool;
}

  • Columns: how many fit is computed from each route's minimum width in rems. Divider widths can be dragged on Pointer and are persisted per machine, as matterfast's layout/widths.rs does today.
  • Stack, Touch: shared-axis push (spring), back::push guard per pushed page, back::preview(top, gesture).under(previous).swipe_back(!route.scrolls_sideways()).
  • Stack, Pointer (narrow desktop window): a 120 ms fade, Alt ← and mouse button 4 go back.
  • The state is a plain Vec<R>, so a UI scenario can start on any route, like matterfast's script.rs.
