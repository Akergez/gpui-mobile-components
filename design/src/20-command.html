Command: one logical action, many entry points

A command has a label, an icon, a GPUI Action, an enabled state, an optional shortcut and a role (primary, normal, destructive, overflow). The same command value renders as a toolbar button, a FAB, a menu item, an action sheet row or a key binding. This follows the Coding Guides rule "model one logical desktop command once". money-manager's More menu (Import CSV… Ctrl Shift I, Export CSV…, Sync) is the reference case.

#[derive(Clone)]
pub struct Command { id: ElementId, label: SharedString, icon: IconName,
                     action: Box<dyn Action>, role: CommandRole, disabled: bool }
impl Command {
    pub fn new(id, label, icon, action: impl Action) -> Self;
    pub fn destructive(self) -> Self;   pub fn overflow(self) -> Self;
    pub fn disabled(self, disabled: bool) -> Self;
}
// The shortcut is not stored here: it is read from the keymap for the action,
// so the menu, the tooltip and the binding cannot disagree.
